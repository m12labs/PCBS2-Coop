# Phase 13 avatar animation and tweening research

Reviewed November 8, 2026 for the public source repo and downloadable BepInEx 6 IL2CPP mod. The installed target is Unity 6000.2.6f2, Windows x64, with a .NET 6 plugin and game-specific Unity interop assemblies. [Plugin project](../../src/PCBS2Coop.Plugin/PCBS2Coop.Plugin.csproj) · [Unity project version](../../unity/PCBS2CoopModels/ProjectSettings/ProjectVersion.txt)

## Recommendation

Use Unity's native Humanoid Animator, the existing CC0 locomotion clips, and a few authored workshop poses. Use ordinary per-frame easing in the existing remote view for visual properties such as prop offsets and label fades. Use inverse kinematics (IK) for hand contact if the baked poses visibly drift. This keeps the animation bundle on the path already used by the mod. ## Can we ship DOTween?

| Option | Use and redistribution | Fit for PCBS2 |
| --- | --- | --- |
| **DOTween Standard** | Free for commercial and noncommercial use. Demigiant permits verbatim source redistribution with its original copyright notices, disclaimers and `readme.txt`. A compiled copy can accompany that source. Private modifications are allowed. Redistributing a modified version is forbidden. The published grant describes compiled redistribution alongside the verbatim source. [Demigiant license](https://dotween.demigiant.com/license.php) · [Upstream license file](https://github.com/Demigiant/dotween/blob/develop/LICENSE) | The Unity binary's compatibility is unproven on this BepInEx target. A port that changes upstream source would require a different grant to distribute. |
| **DOTween Pro** | Paid per person working on the Unity project. Redistribution inside Unity plugins requires copyright-owner authorization and the specified notices. [Demigiant Pro terms](https://dotween.demigiant.com/license.php) | Excluded under the no-cost, proven-redistribution requirement. |
| **Retromono.Tweens 1.0.1** | Publisher identifies it as MIT and links its notice file from the source repo. MIT allows use, modification and redistribution with the copyright and permission notice. The published .NET Standard 2.0 target declares zero dependencies. Preserve the exact package notice when staging it. [Publisher repository and MIT designation](https://github.com/EvidentlyCube/Retromono.Tweens) · [Published package](https://www.nuget.org/packages/Retromono.Tweens/1.0.1) · [MIT text](https://opensource.org/license/mit) | Best library candidate if several scripted sequences become necessary. It takes elapsed time through `Advance(TimeSpan)` and supports serial and parallel steps and callbacks. The plugin could own the tick and use a scalar callback to apply Unity transforms. That architecture avoids injecting a third-party Unity component. Package execution in this game is untested. |
| **LitMotion** | The author's MIT license permits source and binary redistribution with its copyright and permission notice. Review the selected release and each extra dependency separately. [Upstream license](https://raw.githubusercontent.com/annulusgames/LitMotion/main/LICENSE) | Unity-oriented and heavier. The author documents Burst, Collections, Mathematics and the Unity job system. The installed game has some corresponding interop assemblies. Their presence alone cannot establish that LitMotion's job scheduling, initialization and binding paths work inside a separately compiled mod. [Installation requirements](https://github.com/annulusgames/LitMotion/blob/main/docs/articles/en/installation.md) · [Architecture](https://github.com/annulusgames/LitMotion/blob/main/docs/articles/en/design-philosophy.md) |
| **Plugin-owned easing** | Project code using math and Unity calls already available in the game. | Smallest fit for visual-only progress from zero to one, then interpolation of positions, rotations or opacity. Scope each effect to the replica's lifetime and let accepted game state decide when it starts and stops. [Existing view update](../../src/PCBS2Coop.Plugin/RemotePlayerView.cs) |

DOTween's upstream `Init` creates a persistent GameObject and adds its own `DOTweenComponent`. Its manual update API changes how a tween advances after initialization. The normal initialization path still adds that component. PCBS2 already injects the mod-owned `CoopRunner` into IL2CPP. A package whose components were compiled for an ordinary Unity project needs a separate interop and class-registration proof here. Unity AssetBundles carry serialized assets and cannot deliver executable C# assemblies. A compatible runtime library would be staged beside the BepInEx DLL, while the avatar bundle stays script-free under the existing builder. [DOTween initialization](https://github.com/Demigiant/dotween/blob/develop/_DOTween.Assembly/DOTween/DOTween.cs) · [DOTween component creation](https://github.com/Demigiant/dotween/blob/develop/_DOTween.Assembly/DOTween/Core/DOTweenComponent.cs) · [DOTween manual update](https://dotween.demigiant.com/documentation.php) · [Il2CppInterop class injection](https://github.com/BepInEx/Il2CppInterop/blob/master/Documentation/Class-Injection.md) · [Unity AssetBundle script support](https://docs.unity3d.com/6000.2/Documentation/Manual/AssetBundlesIntro.html) · [Plugin entry point](../../src/PCBS2Coop.Plugin/Plugin.cs)

## How the motions fit the game

- **Base movement.** Use the replicated feet position and yaw to move the replica root. Feed smoothed speed into the existing in-place locomotion controller with root motion disabled. Use a masked upper-body layer for carry, attention and working poses. `CoopController` already sends movement at 20 Hz and supplies accepted carry and some activity state. [CoopController.cs](../../src/PCBS2Coop.Plugin/CoopController.cs) · [Unity animation layers](https://docs.unity3d.com/6000.2/Documentation/Manual/AnimationLayers.html)
- **Hand and head targets.** Read-only inspection of the installed `UnityEngine.AnimationModule.dll` metadata found Animator `CrossFade`, `GetBoneTransform`, root-motion and layer controls, and the position, rotation and weight wrappers for IK and gaze. Unity's native IK path needs a valid Humanoid Avatar, an active layer with IK Pass enabled and a callback component on the Animator GameObject. The mod can test a separately injected component on the spawned instance. The wrappers establish an implementation path. Callback delivery and native execution remain untested in PCBS2. Baked poses can be used before that proof. [Unity 6.2 OnAnimatorIK](https://docs.unity3d.com/6000.2/Documentation/ScriptReference/MonoBehaviour.OnAnimatorIK.html) · [Il2CppInterop class injection](https://github.com/BepInEx/Il2CppInterop/blob/master/Documentation/Class-Injection.md)
- **Actor state.** Use the actual carry fact, `ActorActivity.WorkingPc` and accepted tool or edit facts for pose selection and local prop targets. The movement packet carries position, yaw and a normalized desktop cursor. Exact free-look pitch, tablet tilt and arbitrary hand targets would need separately agreed inputs if required. A visual hold or reach toward a known bench can be derived locally. [PlayerState and MonitorCursor](../../src/PCBS2Coop.Network/Protocol.cs) · [ActorActivity.cs](../../src/PCBS2Coop.Network/ActorActivity.cs) · [CoopController.cs](../../src/PCBS2Coop.Plugin/CoopController.cs)
- **Runtime package boundary.** The installed interop scan found `Unity.Burst`, `Unity.Collections` and `Unity.Mathematics`, with no assembly names matching Unity Animation Rigging, DOTween, LeanTween, PrimeTween, LitMotion or Unity.Jobs. Animation Rigging is separately licensed under the Unity Companion License and adds components and job evaluation. Native Animator or editor-baked poses need fewer assumptions. Keep the working async asset load and the script-free prefab contract. [Unity Animation Rigging license](https://docs.unity3d.com/Packages/com.unity.animation.rigging@1.4/license/LICENSE.html) · [Unity Companion License](https://unity.com/legal/licenses/unity-companion-license) · [PlayerModelAssets.cs](../../src/PCBS2Coop.Plugin/PlayerModelAssets.cs) · [BuildPlayerBundle.cs](../../unity/PCBS2CoopModels/Assets/Editor/BuildPlayerBundle.cs)

## First in-game acceptance pass

1. In Unity, preview idle, walk, sprint, turn, carry and a single bench reach with the selected model. Inspect shoulders, elbows, stride and both hands. Verify root position stays controlled by the mod, with no backwards facing or doubled root movement.
2. In an isolated two-game session, swap roles and compare the model's look, hold and release while walking and turning. Enter and leave one bench action. Watch both during a pause, a disconnect and a rejoin. The replica should display the current carry or action state on spawn, and despawn should release props and cancel any queued visual effects.
3. If an optional runtime tween library or IK component is used, stage only the compatible binaries and required notices. Run one cancellable visual transition and verify clean scene unload and rejoin. Gameplay callbacks remain owned by the existing accepted edit/replay path.
